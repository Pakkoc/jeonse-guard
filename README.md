# jeonse-guard

**주소 한 줄로 전세 계약 전 안전진단, 계약 후엔 보증금 워치독.**

국토교통부 실거래가·건축물대장 같은 공공데이터를 교차 조회해서,

- **계약 전** — 전세가율, 건물 용도(근린생활시설 여부), 실거래 표본을 *산출 근거와 함께* Markdown 리포트로 만들어 주고
- **계약 후** — 매일 아침 같은 주소를 다시 스캔해서 새 실거래 등장, 전세가율 80% 경계 통과, 대장 변경이 감지되면 GitHub Issue로 알려 줍니다.

외부 의존성 0개(순수 Python 표준 라이브러리), API 키 없이 바로 시작할 수 있습니다.

## 데모

```console
$ python -m jeonse_guard.cli scan "서울 마포구 성산동 200-1" --name 성산시영 --area 50 --deposit 30000
```

30초 정도면 리포트가 [`reports/`](reports/)에 저장됩니다. **실제 데이터로 생성한 샘플**:

- [정상 시나리오 — 전세가율 24.4%](reports/sample-seongsan-normal.md) (보증금 3억, 매매 중위 12억2,750만원 · 표본 98건)
- [주의 시나리오 — 전세가율 85.5%, warn 발화](reports/sample-seongsan-high-ratio.md) (시세보다 높은 보증금 10억5천을 제시받았다고 가정)

리포트에는 **확정 주소·매매/전세 중위가·전세가율 산출식**(확인된 사실), **검토 신호**(근거 필수), 자동 조회가 불가능한 항목의 **직접 확인 체크리스트**(등기부 근저당 / 선순위보증금 / 전입세대 열람 / 보증보험 가입 가능 여부 / 임대인 세금완납증명)가 담깁니다.

> 이 리포트는 공공데이터 기반 참고 자료이며 계약 판단의 근거가 아닙니다. 반드시 등기부등본과 전문가 확인을 거치세요.

## 3분 시작

Python 3.11 이상만 있으면 됩니다.

```console
$ git clone https://github.com/<your-id>/jeonse-guard && cd jeonse-guard
$ pip install -e .
$ jeonse-guard scan "서울 마포구 성산동 200-1" --name 성산시영 --area 50 --deposit 30000
```

설치 없이 바로 실행해도 됩니다:

```console
$ python -m jeonse_guard.cli scan "서울 마포구 성산동 200-1" --deposit 30000
```

### `scan` 옵션

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `address` (위치 인자) | 지번 주소. 예: `"서울 마포구 성산동 200-1"` | 필수 |
| `--deposit` | 전세보증금 (만원 단위, `30000` = 3억). 없으면 전세 실거래 중위값으로 대체 | 없음 |
| `--name` | 단지/건물명 필터. 예: `성산시영` | 없음 |
| `--area` | 전용면적 ㎡. ±15% 면적대로 표본을 좁힘 | 없음 |
| `--asset` | 자산 유형: `apartment` \| `villa` \| `officetel` | `apartment` |
| `--months` | 실거래 조회 개월 수 | `12` |
| `--out` | 리포트 저장 디렉토리 | `reports` |
| `--json` | stdout에 Markdown 대신 JSON 출력 | 꺼짐 |

`--name`/`--area`를 주면 표본을 단지·면적대로 좁히고, 좁힌 표본이 0건이면 자동으로 한 단계씩 되돌립니다(단지+면적 → 단지 → 면적 → 지역구). 어떤 수준이 적용됐는지는 리포트의 `match_scope`에 그대로 적힙니다.

### `watch` — 보증금 워치독

```console
$ cp watchlist.example.toml watchlist.toml   # 내 계약 정보로 수정
$ jeonse-guard watch
```

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `--watchlist` | 감시 목록 TOML 경로 | `watchlist.toml` |
| `--snapshots` | 스냅샷 저장 디렉토리 | `snapshots` |
| `--reports` | 리포트 저장 디렉토리 | `reports` |

실행할 때마다 watchlist의 각 주소를 재스캔해 직전 스냅샷과 비교하고, 변화가 있으면 stdout에 한 줄당 이벤트 JSON 하나를 출력합니다. 이벤트 종류는 4가지입니다:

- `new_trade` — 새 매매 실거래 등장
- `ratio_crossed` — 전세가율이 80% 경계를 아래→위로 통과
- `building_changed` — 건축물대장 주용도·사용승인일 변화
- `scan_failed` — 스캔 자체가 실패 (스냅샷은 보존)

첫 실행은 기준선 스냅샷만 저장하고 이벤트를 만들지 않습니다.

### 건축물대장 섹션 활성화 (선택)

정직하게 말씀드리면, **건축물대장 섹션은 현재 기본적으로 "확인 불가(unavailable)"로 표시됩니다.** 공용 프록시에 건축물대장 라우트가 아직 배포되지 않았기 때문입니다. 이 경우에도 리포트는 실거래·전세가율만으로 완성되며, 확인 불가 사실이 `section_unavailable` 신호로 명시됩니다.

활성화하려면 무료 키 하나면 됩니다:

1. [공공데이터포털](https://www.data.go.kr/data/15134735/openapi.do)에서 **건축HUB 건축물대장정보 서비스(데이터셋 15134735)** 활용신청 — 무료, 자동승인
2. 발급받은 인증키를 환경변수로 설정:

```console
$ export DATA_GO_KR_API_KEY="발급받은-인증키"
$ jeonse-guard scan "서울 마포구 성산동 200-1" --deposit 30000
```

키가 있으면 프록시 실패 시 자동으로 공공데이터포털 직접 호출 모드로 전환됩니다. (`KSKILL_BUILDING_REGISTER_API_KEY`가 설정돼 있으면 그쪽을 우선 사용합니다.)

## Fork 해서 브라우저만으로 쓰기 (GitHub Actions)

로컬에 Python이 없어도 됩니다. Fork 한 번이면 브라우저에서 진단하고, 매일 아침 워치독이 돌아갑니다.

1. 우상단 **Fork** 클릭
2. 내 fork의 **Actions** 탭에서 워크플로 활성화 (fork는 기본 비활성)
3. **일회성 진단** — Actions → `scan` → *Run workflow* → 주소(필수)와 보증금·단지명·면적(선택) 입력 → 실행이 끝나면 **Summary 화면에서 리포트를 바로 확인**할 수 있고, `reports/`에도 커밋됩니다
4. **워치독** — `watchlist.example.toml`을 `watchlist.toml`로 복사해 내 계약 정보로 수정 후 커밋하면, `watch` 워크플로가 **매일 07:00 KST**에 자동 실행됩니다. 변화가 감지되면 저장소에 Issue가 생성되고, 스냅샷·리포트가 커밋됩니다. 수동 실행(*Run workflow*)도 가능합니다. **fork는 Issues 기능이 기본으로 꺼져 있으니** *Settings → General → Features*에서 **Issues**를 켜 두세요 (안 켜면 알림 Issue 생성이 실패합니다)
5. (선택) *Settings → Secrets and variables → Actions*에 `DATA_GO_KR_API_KEY`를 등록하면 건축물대장 섹션이 활성화됩니다

> **프라이버시 참고**: public 저장소의 fork는 public입니다. watchlist에는 내 주소·보증금이 들어가므로, 공개가 부담스러우면 fork 대신 이 저장소를 clone해서 **private 저장소로 push**해 쓰는 것을 권장합니다. 워크플로는 동일하게 동작합니다.

## 검토 신호 4종

근거가 있을 때만 생성되며, 각 신호에는 산출 수치와 원문이 그대로 붙습니다.

| 신호 | 수준 | 조건 |
|---|---|---|
| `high_jeonse_ratio` | warn | 전세가율 ≥ 80% (보증금 ÷ 매매 중위가). 전세가율이 높을수록 집이 팔려도 보증금을 전액 회수하지 못할 여지가 커집니다 |
| `nongsaeng_building` | warn | 건축물대장 주용도·기타용도에 "근린생활" 포함. 근린생활시설은 주거용 건물이 아니어서 전세보증금 반환보증 가입이 제한될 수 있습니다 |
| `no_price_reference` | info | 매매 실거래 표본이 3건 미만이라 시세 참조가 어려움 |
| `section_unavailable` | info | 조회하지 못한 데이터 섹션이 있음 (사유 명시) |

## 판정 철학 — 단정하지 않습니다

이 도구는 **"안전 / 위험" 판정을 내리지 않습니다.** 공공데이터로 확인 가능한 사실과 그 산출 근거만 보여주고, 판단은 사용자와 전문가의 몫으로 남깁니다.

- 신호는 조건이 충족될 때만, 산출식·표본 수·원문과 함께 생성됩니다
- 주소가 하나로 확정되지 않으면 추정하지 않고 후보를 보여주며 중단합니다
- 자동화가 불가능한 핵심 확인 항목 — **등기부등본 근저당, 선순위보증금, 전입세대 열람, 보증보험 가입 가능 여부, 임대인 세금완납증명** — 은 모든 리포트에 직접 확인 체크리스트로 고정 안내됩니다

> **면책**: 이 리포트는 공공데이터 기반 참고 자료이며 계약 판단의 근거가 아닙니다. 반드시 등기부등본과 전문가 확인을 거치세요. 데이터 출처의 갱신 지연·누락으로 실제와 다를 수 있습니다.

## 데이터 출처와 크레딧

| 데이터 | 출처 |
|---|---|
| 매매·전월세 실거래가 | 국토교통부 실거래가 공개시스템 |
| 건축물대장 표제부 | 국토교통부 건축HUB 건축물대장정보 서비스 ([데이터셋 15134735](https://www.data.go.kr/data/15134735/openapi.do)) |
| 주소 지오코딩 | 카카오 로컬 API |

공공 API 호출은 [NomaDamas/k-skill](https://github.com/NomaDamas/k-skill) 프로젝트의 공용 프록시(`k-skill-proxy`)를 경유합니다. k-skill은 MIT 라이선스로 공개되어 있으며, 이 프로젝트의 일부 데이터 어댑터는 k-skill 스크립트를 참조해 작성되었습니다.

## 프록시 사용 예절

기본 프록시는 커뮤니티가 무료로 운영하는 공용 인프라입니다. **개인의 소량 조회 용도로만 사용해 주세요.**

- 대량 조회, 상업적 사용, 높은 빈도의 자동화가 필요하면 [공공데이터포털](https://www.data.go.kr)에서 무료 키를 직접 발급받아 쓰세요
- `KSKILL_PROXY_BASE_URL` 환경변수로 자체 배포한 프록시로 교체할 수 있습니다
- 건축물대장은 `DATA_GO_KR_API_KEY` 설정 시 프록시를 거치지 않는 직접 호출 모드로 동작합니다
